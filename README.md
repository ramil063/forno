# forno — микросервисы на Go

Учебный проект: микросервисная доставка пиццы. Пять сервисов на двух протоколах
(HTTP и gRPC), PostgreSQL, Kafka, Redis и полная наблюдаемость. Всё пишется руками —
цель не «сделать быстро», а разобраться, как это устроено в продакшене.

План по этапам, журнал прогресса и договорённости — в [ROADMAP.md](ROADMAP.md).

## Что уже работает

- Docker-образ `forno/tools`: Go 1.27.1 и инструменты (`buf`, `protoc-gen-go`, `mockery`,
  `golangci-lint`, `air`). Версия Go меняется одной строкой в `docker/Dockerfile.tools`
- Монорепозиторий на `go.work` с тремя модулями, каждый сервис — отдельный Go-модуль
- Форматирование и проверки: `make fmt`, `make fmt-diff`, `make lint`
  (`gofmt` + порядок импортов `gci` + набор линтеров)
- PostgreSQL 17 поднимается одной командой; порты и доступы — в `.env`, которого нет в git

Самих сервисов пока нет — только заглушки, которые печатают своё имя.

## Быстрый старт

```bash
git clone https://github.com/ramil063/forno.git && cd forno
make image    # собрать образ с инструментами, нужно один раз, ~5 минут
make hooks    # подключить git-хуки, один раз после клонирования
make db-up    # поднять PostgreSQL; .env создастся из .env.example сам
make build    # собрать все модули
make lint     # форматирование и проверки
```

`make` без аргументов печатает список всех команд.

## Сервисы

| Сервис | Роль | Протокол | Статус |
|---|---|---|---|
| `order-service` | оформление заказов, точка входа | HTTP наружу, gRPC внутрь | заглушка |
| `inventory-service` | склад ингредиентов: остатки и резерв | gRPC | заглушка |
| `payment-service` | оплата, своей базы нет | gRPC | заглушка |
| `kitchen-service` | готовит заказ по событию оплаты | Kafka | ещё нет |
| `auth-service` | регистрация, логин, сессии | gRPC + Redis | ещё нет |
| `notification-service` | уведомление клиенту | Kafka | бонус, если останется время |

Здесь же будет описание каждого сервиса по мере появления: что делает, какие методы
отдаёт, с кем и как общается.

## Как устроен репозиторий

```
docker/Dockerfile.tools   образ с Go и инструментами
services/*                сервисы, каждый — отдельный Go-модуль
go.work                   воркспейс, связывает модули между собой
docker-compose.yml        инфраструктура: tools и PostgreSQL (дальше Kafka и Redis)
Makefile                  все команды проекта
.golangci.yml             формат и проверки кода
.editorconfig             отступы и переводы строк для редактора
ROADMAP.md                план по этапам и журнал прогресса
```

## Порты и адреса

До одной базы два разных адреса — это не опечатка, а особенность Docker:

| Откуда подключаешься | Хост | Порт |
|---|---|---|
| С хоста: `psql`, GUI-клиент, `make psql` | `localhost` | `5440` |
| Из контейнера `tools`: код сервисов и тесты | `postgres` | `5432` |

Порты выбраны вне диапазонов, занятых другими проектами на этой машине.
Значения для локальной разработки лежат в `.env` (в git не хранится),
шаблон — `.env.example`.

## Как здесь принято работать с git

В `main` напрямую не коммитим: один этап — одна ветка, дальше PR и squash-мерж.
Правила и полный цикл команд описаны в [ROADMAP.md](ROADMAP.md), раздел «Git: ветки, коммиты, PR».

# forno — инструкции для агента

Учебный проект: микросервисы на Go, тема «доставка пиццы». Пользователь изучает технологии
и **пишет код сам**. План и текущее состояние — в `ROADMAP.md` (источник правды),
описание проекта — в `README.md`. Начиная работу, прочитай оба.

## Роли

- Код пишет пользователь. Агент даёт карту проекта, карту задачи (какие файлы нужны
  и с какими контрактами), ревью и наводки при застревании.
- Готовый код от агента — только для сборки, конфигов и инфраструктуры (Makefile, `buf.yaml`,
  `docker-compose.yml`, `go.mod`, `.gitignore`, миграции) и для сравнения, когда причина
  ошибки уже найдена.
- Файлы пользователя без просьбы не править.
- Тесты пишем сразу, а не «потом».
- Перед началом этапа — разложить его на задачи по 0.5–2 часа и показать список.
- ТЗ задачи кладётся файлом в `tasks/stage-N/` (номер в имени — номер задачи в раскладке
  этапа), а не только пишется в чат. Оглавление — `tasks/README.md`.

## Git

- В `main` напрямую не коммитить и не пушить: локальные хуки в `.githooks/` это блокируют,
  на GitHub ветка защищена.
- Ветка — под одну задачу (`feat/pgx-pool`, `fix/...`, `docs/...`, `chore/...`), живёт
  день-два; длинных веток «на этап» нет. Этап — единица плана, а не git.
- Один PR — одна задача; при **squash**-мерже он становится одним коммитом в `main`,
  поэтому заголовок PR пишем как сообщение коммита (императив: «добавить миграцию ингредиентов»).
- Перед PR должно быть чисто: `make fmt-diff`, `make lint`, `make test-race`.
- После мержа ветку удалить — и на GitHub, и локально.
- Осознанный обход хуков: `FORNO_ALLOW_MAIN_COMMIT=1` / `FORNO_ALLOW_MAIN_PUSH=1`.
- Git-операции (ветки, коммиты, PR, мерж) агент ведёт сам, пользователь подключается,
  когда разбираем CI и хуки на PR. Код при этом по-прежнему пишет пользователь.

## Окружение

Go и все инструменты живут внутри Docker-образа `forno/tools`, локальный Go не используется.
Работать через `make`: `make help` — список команд, `make image` — собрать образ,
`make db-up` / `make db-down` / `make psql`, `make build`, `make test`, `make test-race`,
`make fmt`, `make fmt-diff`, `make lint`, `make lint-fix`.

- `.env` создаётся сам из `.env.example` и в git не хранится.
- До базы два адреса: с хоста `localhost:5440`, из контейнера `postgres:5432`.
- `go.work` в корне запрещает `./...` из корня — Makefile обходит модули по одному.

# Задача 1.3 — cmd/checkenv: параллельная проверка окружения

- **Этап:** 1, «PostgreSQL с самого начала: инфраструктура и хранилище»
- **Оценка:** ~1.5–2 часа
- **Зависимости:** задача 2 (пул `pgx`) — оттуда берётся конструктор и `Ping`.
- **Артефакт:** `services/inventory-service/internal/checkenv/checkenv.go` (+ тесты)
  и `services/inventory-service/cmd/checkenv/main.go`
- **Готово, когда:** одна команда говорит, что с окружением — и называет, что именно сломано,
  а не просто «ошибка».

Это первая задача, где появляется `errgroup` (см. `ROADMAP.md`, раздел про многопоточность).

## Файлы

```
services/inventory-service/
  cmd/checkenv/main.go               тонкий: контекст с таймаутом, DSN, вызов, exit code
  internal/checkenv/checkenv.go      сами проверки; ничего не знает про os.Exit и stdout
  internal/checkenv/checkenv_test.go
```

## Три проверки

1. **База отвечает** — `Ping` с таймаутом.
2. **Миграции накатаны** — в базе есть таблицы схемы (`units`, `warehouses`, `ingredients`,
   `ingredient_stock`) и последняя запись в `goose_db_version` помечена как применённая.
   Проверка «таблица версий существует» ничего не значит: пустая база её тоже не имеет,
   а вот база после отката имеет.
3. **Пул отдаёт соединение** — `Acquire`, короткий запрос, `Release`, и в вывод заодно
   статистика пула: всего / свободно / занято / максимум.

## Требования

- Три проверки идут параллельно через `errgroup.WithContext`: упала одна — остальные
  отменяются по контексту, а не продолжают долбить базу.
- Но показать нужно **все** проблемы, а не первую. Поэтому результат каждой проверки —
  своя строка (или свой элемент) в срезе: каждая горутина пишет только в свой слот,
  `errgroup.Wait()` даёт синхронизацию, мьютекс здесь не нужен — объясни в коммите, почему.
  Итог собирается через `errors.Join`.
- Общий таймаут на всю команду (например, 10s) создаётся в `main`. В библиотеку контекст
  приходит первым аргументом.
- `os.Exit` — только в `main`. Пакет `checkenv` не знает ни про stdout, ни про код возврата:
  на этапе 7 этот же код станет health-check сервиса.
- Список проверок — данные, а не копипаста: добавить четвёртую проверку = одна строка в списке.
- Вывод: строка на проверку (имя + ok/ошибка), затем итог. Ошибки не глотать.
- Тексты ошибок по-человечески: «база недоступна: …», «миграции не накатаны: последняя
  применённая версия — 0», а не «error» и не голый `%v` от pgx.

## Тесты (сразу, не потом)

Проверки должны подменяться в тестах, без базы и без сети. Скорее всего появится маленький
интерфейс «проверка» (`Name()` + `Check(ctx) error` или функция с таймаутом) — объяви его там,
где он используется, то есть в `checkenv`.

- табличный тест с фейками: все три ок; падает вторая; падают все три → в итоговой ошибке
  три текста, а не один;
- тест на таймаут: проверка, которая спит дольше контекста, должна вернуть ошибку отмены,
  а не висеть;
- `make test-race` должен быть зелёным — здесь он ловит именно то, ради чего мы городим
  срез вместо `map`.

## Как проверю

- [ ] `make shell` → `cd services/inventory-service && go run ./cmd/checkenv` → три ok, exit 0
- [ ] `make db-down` → та же команда → внятные ошибки про базу, exit ≠ 0, без паники
      и без ожидания «до посинения»
- [ ] `make migrate-down` дважды → база жива, таблиц нет → падает только проверка миграций,
      две другие зелёные (это и есть доказательство, что проверки независимы)
- [ ] `make migrate-up` возвращает всё на место
- [ ] `make test-race` зелёный, тесты не требуют базы
- [ ] в новом коде нет `context.Background()` вне `main` и нет `context.TODO()`
- [ ] по логу видно, что проверки идут параллельно: общее время ≈ самое долгое, а не сумма трёх

# Задача 1.7 — интеграционные тесты репозитория против реальной базы

- **Этап:** 1, «PostgreSQL с самого начала: инфраструктура и хранилище»
- **Оценка:** ~2 часа
- **Зависимости:** задачи 1.2 (пул), 1.4 (схема), 1.6 (репозиторий) — готовы
- **Артефакт:** `services/inventory-service/internal/storage/postgres/ingredient_integration_test.go`
- **Готово, когда:** `make test-integration` на живой базе проходит, а обычный
  `make test-race` эти тесты не запускает вовсе.

Это последняя задача этапа. После неё этап 1 закрывается тегом `v0.1`.

## Как отделяем интеграционные тесты

Первая строка файла:

```go
//go:build integration
```

Это **тег сборки**: без флага `-tags=integration` файл вообще не компилируется в тестовый
бинарник. Значит `make test-race`, `make test` и CI без базы остаются зелёными и ничего
не знают про интеграционные тесты. Запуск — только явно:

```bash
make test-integration        # цель добавлю я, это инфраструктура
```

Почему не проверка `POSTGRES_DSN != ""`: внутри контейнера эта переменная задана **всегда**,
и тогда интеграционные тесты побежали бы в обычном `make test-race` — то есть начали бы
требовать живую базу от любой проверки.

## Изоляция тестов

Пул создаётся один раз на пакет, а **каждый тест работает в своей транзакции** и в конце
откатывается:

```go
func newTestRepo(t *testing.T) (*pgxpool.Pool, *IngredientRepository, context.Context) {
	t.Helper()
	dsn := os.Getenv("POSTGRES_DSN")
	if dsn == "" {
		t.Fatal("POSTGRES_DSN не задан: тест запускается внутри контейнера (make test-integration)")
	}
	ctx := context.Background()
	pool, err := New(ctx, Config{DSN: dsn, ApplicationName: "inventory-service-test"})
	if err != nil {
		t.Fatalf("пул: %v", err)
	}
	t.Cleanup(pool.Close)

	tx, err := pool.Begin(ctx)
	if err != nil {
		t.Fatalf("транзакция: %v", err)
	}
	t.Cleanup(func() { _ = tx.Rollback(ctx) })

	return pool, NewIngredientRepository(tx), ctx
}
```

Здесь и работает `DBTX` из задач 1.5–1.6: репозиторий принимает и пул, и транзакцию, поэтому
тесту достаточно передать `tx`. `TRUNCATE` внутри этой транзакции допустим: он делает тест
независимым от того, что уже лежит в таблице, а откат возвращает строки обратно. Главное —
не чистить базу вне транзакции.

## Что обязательно проверить

1. **Круговой рейс:** `Create` возвращает `id > 0`; `Get` по этому `id` отдаёт те же `name`,
   `unit_id`, `description`; `created_at` и `updated_at` не нулевые; `archived_at == nil`.
2. **Nullable:** создать без описания → `Get.Description == nil`; создать с описанием →
   указатель на то же значение.
3. **Не найдено:** `Get` с несуществующим `id` → `errors.Is(err, errIngredientNotFound)`.
4. **Уникальность:** два `Create` с одним именем в разном регистре («Мука» и «мука») →
   второй возвращает `errors.Is(err, errIngredientAlreadyExists)`.
5. **Список:** создать несколько ингредиентов с разными именами → `List` возвращает их
   по алфавиту; архивный (`UPDATE ingredients SET archived_at = now()`) в список не попадает.
6. **Пагинация:** `List(limit, offset)` отдаёт нужное окно; отрицательные значения —
   ошибка, не паника.

## Требования

- Тестовые имена делай уникальными (например, с суффиксом из `t.Name()`), даже несмотря
  на откат: это защищает от сюрпризов, если в базе уже лежат похожие строки.
- Для `unit_id` возьми существующую единицу внутри той же транзакции:
  `SELECT id FROM units WHERE short_name = 'г'`. Справочник наполняется миграцией.
- Если база недоступна — тест должен упасть с понятным сообщением за секунды,
  а не висеть: пул уже ограничивает соединение таймаутом из задачи 1.2.
- Никаких `time.Sleep` для «подождать базу»: если нужно ждать — это ошибка теста.
- Обычные тесты (`make test-race`) не должны измениться: тег сборки гарантирует,
  что этот файл в них не попадает.

## Как проверю

- [ ] `make test-race` без тега — зелёный, интеграционные тесты не выполняются
- [ ] `make test-integration` внутри контейнера — все сценарии выше зелёные
- [ ] после `make db-down` `make test-integration` падает с понятной ошибкой, а не висит
- [ ] после прогона в базе не остаётся тестовых строк (проверю `SELECT count(*)`)
- [ ] `make fmt-diff`, `make lint` — чистые

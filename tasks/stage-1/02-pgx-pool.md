# Задача 1.2 — пул соединений pgx и проверка живости базы

- **Этап:** 1, «PostgreSQL с самого начала: инфраструктура и хранилище»
- **Оценка:** ~1.5 часа
- **Зависимости:** задача 4 (схема накатана) — готова. База поднимается `make db-up`.
- **Артефакт:** `services/inventory-service/internal/storage/postgres/pool.go` + правка `cmd/main.go`
- **Готово, когда:** сервис при старте подключается к базе, сообщает об этом и падает
  с понятной ошибкой, если база недоступна или DSN пустой.

## Требования

- DSN приходит снаружи — `os.Getenv("POSTGRES_DSN")` в `main`. Ни строки подключения,
  ни пароля в коде. Пустой DSN — внятная ошибка конфигурации, а не паника и не
  `dial tcp: missing address`.
- Пул настраивается осознанно: `MaxConns`, `MinConns`, `MaxConnLifetime`, `MaxConnIdleTime`,
  `HealthCheckPeriod`. В коммите объясни, почему такие значения. Дефолты `pgxpool.ParseConfig`
  стоит прочитать: часть параметров там уже разумная.
- `application_name=inventory-service` в `RuntimeParams` — в `pg_stat_activity` видно, кто пришёл.
- `statement_timeout` (например, 5s) — чтобы одна кривая выборка не держала соединение вечно.
- Проверка при старте: `Ping` с отдельным таймаутом, а не «пока не отвалится».
- При старте же выполни `SELECT current_setting('application_name'), current_setting('statement_timeout')`
  и положи в лог — так ты докажешь сам себе, что настройки доехали до соединения.
- `defer pool.Close()` — что открыли, то и закрыли.
- Ошибки оборачиваются через `%w`, сравниваются через `errors.Is/As`. Склейка строк и `==` — нет.
- Контекст создаётся только в `main` и передаётся первым аргументом. `contextcheck` в линтере
  это проверяет, `context.TODO()` в новом коде не должен появиться вовсе.

## Тесты (сразу, не потом)

Без базы, таблицей: пустой DSN → ошибка; мусорный DSN (`не-dsn`) → ошибка, и через `errors.As`
достаётся тип ошибки pgx. Это дешёвые тесты, которые ловят регрессию в разборе DSN.

Тест с живой базой в этой задаче не нужен — он в задаче 7. Если хочется сейчас, делай через
переменную окружения и `t.Skip`, когда `POSTGRES_DSN` не задан.

## Как проверю

- [ ] `make build`, `make test-race`, `make lint` — зелёные
- [ ] `make shell` → `cd services/inventory-service && go run ./cmd` — в выводе видно, что база отвечает,
      `application_name` и `statement_timeout` те, что заданы
- [ ] то же с `POSTGRES_DSN=postgres://forno:неверный@postgres:5432/forno` — понятная ошибка,
      exit code ≠ 0, без паники
- [ ] то же с пустым `POSTGRES_DSN` — ошибка конфигурации, а не таймаут соединения
- [ ] сервис не ждёт вечно: при недоступной базе падает за стартовый таймаут, а не через минуту
